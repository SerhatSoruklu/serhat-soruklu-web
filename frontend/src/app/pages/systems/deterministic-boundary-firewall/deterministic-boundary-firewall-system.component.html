SYSTEM PURPOSE

What It Does

BoundaryGate is a shared preflight gate used by a small Python client and a matching MCP server. It inspects text before outbound model or tool calls. If configured tripwires match, it returns a refusal payload. Otherwise the request is allowed to proceed.

BOUNDARY MODEL

Bounded, Not Magical

DBF is a deterministic phrase and pattern boundary. It is not a general semantic firewall, and the repository intentionally avoids claiming exhaustive synonym or full obfuscation resistance.

Normalization

Text is normalized before checks, but normalization is partial and documented as a bounded surface.

Tripwire Matching

blocked_terms are exact configured matches, not semantic extraction or broad intent inference.

Refusal Payload

Matched probes return structured refusal payloads instead of silently passing through to execution.

Transport Interception

The boundary sits before outbound model or tool calls so risky text can be rejected early.

Client/Server Parity

The Python client and MCP server share the same boundary model to reduce drift between surfaces.

Release Gate

Quality checks act as a release gate for the artifact, not as proof of complete security coverage.

ATTACK SURFACE

Built To Be Attacked

The repository intentionally invites bypass attempts across zero-width obfuscation, homoglyphs, mixed encodings, split-token prompts, role-play or policy puppetry, context smuggling, semantic paraphrase, transport reshaping, adversarial suffixes, and false-positive probes.

The goal is a proof surface and attack target: a clear boundary that can be tested, broken, documented, and improved without pretending to solve all semantic safety problems.
